## Summary

This phase is far smaller than the ROADMAP's "22 files" estimate suggests. A full grep of `src/` for every pose component (both `Bambu*` PascalCase names and `bambu-*` kebab paths) shows that **only one pose component is still imported anywhere: `BambuLoading`**, used in exactly **6 files, all under `src/components/auth/`**. The other 7 pose components (`bambu-base`, `bambu-empty`, `bambu-error`, `bambu-preparing`, `bambu-success`, `bambu-travel`, `bambu-welcome`) have **zero importers** — Phases 11 and 13, plus prior cleanup, already removed every consumer. They are pure dead-code file deletions.

`bambu-base.tsx` (the shared `Bambu` primitive + `BambuPose` type) has **zero importers** — not even the other pose components import it; each pose component re-implements its own inline panda SVG. So `bambu-base` is independently deletable. `bambu-video.tsx` is completely self-contained: it imports only React hooks, defines its own `videoMap`, and has **no dependency on `bambu-base` or any pose component** — it survives cleanly with no changes.

Every `BambuLoading` usage is identical in shape: an inline button spinner rendered while a form action is `pending` (`{pending ? <BambuLoading size={N} /> : t('...submit')}`). The codebase **already has a canonical inline CSS spinner** used in `coupon-input.tsx` and `cart-drawer.tsx` — a `<span>` with `animate-spin`. The replacement is a direct, mechanical swap to that existing pattern. No i18n keys, no image/lottie assets, and no `public/` files are orphaned by deleting the pose components (their SVGs are inline; the `/bambu/*.mp4` assets belong to `bambu-video.tsx` and stay).

**Primary recommendation:** Delete 8 pose files. In the 6 auth files, replace `<BambuLoading size={N} />` with the existing inline CSS spinner `<span className="inline-block w-4 h-4 border-2 border-current border-t-transparent rounded-full animate-spin" />`. Add a stable `aria-label` to loading buttons so accessible-name-based tests stay green. Update one test mock (`top-up-modal.test.tsx` mocks `bambu-video` only — no change needed; verify it). Verify with grep-zero + `tsc` + `npm test` + `next build`.

## Architecture Patterns

### Replacement pattern (apply uniformly to all 6 sites)
**What:** Swap `<BambuLoading size={N} />` for the codebase's canonical inline spinner; keep the `pending`-ternary structure.

```tsx
// BEFORE (e.g. login-form.tsx L98-100)
<Button type="submit" disabled={pending} className="w-full">
  {pending ? <BambuLoading size={24} /> : t('login.submit')}
</Button>

// AFTER — existing pattern from coupon-input.tsx:147 / cart-drawer.tsx:178
<Button type="submit" disabled={pending} className="w-full" aria-label={t('login.submit')}>
  {pending
    ? <span className="inline-block w-4 h-4 border-2 border-current border-t-transparent rounded-full animate-spin" />
    : t('login.submit')}
</Button>
```
And delete the import line `import { BambuLoading } from '@/components/bambu/bambu-loading';`.

### Anti-Patterns to Avoid
- **Deleting the adjacent `BambuVideo` import** in files 4/5/6 — it sits one line below the `BambuLoading` import. Only remove `bambu-loading`.
- **Introducing a new `<Spinner>` component** — out of scope ("existing primitive only"). The inline span IS the established primitive.
- **Adding a barrel re-export or new dependency** — none needed; `motion`/`lucide-react` already present.
- **Touching `public/bambu/`** — no asset is orphaned.

## Common Pitfalls

### Pitfall 1: Accessible-name regression on OAuth/submit buttons
**What goes wrong:** While `pending`, the button's text children are replaced by the spinner. A spinner `<span>` has no accessible text, so `getByRole('button', { name: /.../ })` in tests (and screen readers) loses the button's name **during the pending state**.
**Why it happens:** `BambuLoading` (an SVG with no `<title>`) had the same flaw, but no current test exercises the pending state by name — so it was latent.
**How to avoid:** Add `aria-label={t('...submit')}` (or the OAuth provider key) to the `<Button>` itself in all 6 files. The `Button` component already forwards `aria-label` (`src/components/ui/button.tsx`). This makes the accessible name independent of children.
**Warning signs:** `oauth-buttons.test.tsx` queries `getByRole('button', { name: /Continue with Google/i })` — keep it green by setting the `aria-label`.

### Pitfall 2: Stale "22 files" estimate from the ROADMAP
**What goes wrong:** A planner following the ROADMAP's "22 files" wording hunts for files that no longer import poses, or assumes checkout/dashboard/PWA/delivery need pose edits.
**Why it happens:** The estimate was made at insertion time; Phases 11 and 13 already removed all non-`BambuLoading` pose consumers, and checkout/dashboard/PWA/delivery use `BambuVideo` (kept), not poses.
**How to avoid:** Trust this RESEARCH's grep-verified inventory: **6 edit files, all in `src/components/auth/`.** The Out-of-Scope table lists every `bambu`-mentioning file that must NOT change.
**Warning signs:** A plan task touching anything outside `src/components/auth/` or `src/components/bambu/`.

### Pitfall 3: `tsc` red-wall if a file is deleted before its usage is migrated
**What goes wrong:** Deleting `bambu-loading.tsx` before editing the 6 auth files leaves 6 dangling imports → `tsc` and `next build` fail.
**Why it happens:** Wrong task ordering.
**How to avoid:** Order the work: (1) edit all 6 auth files to remove `BambuLoading` import + swap usage, (2) THEN delete the 8 pose files. The 7 unreferenced pose files can be deleted at any time; only `bambu-loading.tsx` is order-sensitive.
**Warning signs:** Build failures naming `bambu-loading`.

### Pitfall 4: `bambu-error` / `bambu-success` / `bambu-loading` name collision with `BambuVideo` variants
**What goes wrong:** A grep for `'loading'` or `'success'` matches `BambuVideo variant="loading"` etc., which are unrelated and must stay.
**Why it happens:** `bambu-video.tsx`'s `videoMap` has keys named `loading`, `success`, `error`, `empty`, `preparing`, `welcome` — identical words to pose names.
**How to avoid:** The grep-zero verification (success criterion 2) targets the **kebab file paths and `Bambu*` PascalCase component names** only — `BambuVideo` and `variant="..."` strings do not match those patterns. Use the exact verification grep below.
**Warning signs:** A verification grep returning hits inside `bambu-video.tsx` or on `variant=` strings — that means the pattern was too loose.
