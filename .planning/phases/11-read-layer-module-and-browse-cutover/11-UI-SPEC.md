# Phase 11 — UI Design Contract

> Visual and interaction contract for the Read-Layer Module and Browse Cutover. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> Phase 11 is a **read-path cutover**, not a feature build. The browse page already exists and ships v1.0 visuals. This contract governs the **four new/changed UI surfaces** the cutover introduces: the shimmer skeleton grid, the inline error banner, the typographic image-fallback card with photo cross-fade, and the search-miss empty state. Everything else (region pills, comparison sheet/bar, plan accordion, header chrome) keeps its existing v1.0 styling unchanged.

## Spacing Scale

Declared values (all multiples of 4 — sourced from existing browse components):

| Token | Value | Tailwind | Usage in this phase |
|-------|-------|----------|---------------------|
| xs | 4px | `gap-1`, `p-1` | Sub-label gap inside cards (`mt-0.5` = 2px is an existing v1.0 exception, see below) |
| sm | 8px | `gap-2`, `py-2` | Region-pill gaps, error-banner internal gaps, button vertical padding |
| md | 16px | `gap-4`, `p-4`, `px-4` | Default grid gap, card padding, page horizontal padding, banner padding |
| lg | 20px | `gap-5`, `md:gap-5` | Grid gap at `md+` breakpoint (existing) |
| xl | 24px | `gap-6`, `pt-6` | Vertical rhythm between browse sections, page top padding |
| 2xl | 32px | `mb-8` | (available; not required this phase) |
| 3xl | 64px | `py-16` | Empty-state vertical padding (search-miss block) |

**Grid contract (skeleton MUST match real grid exactly — no layout shift):**
- Country grid: `grid grid-cols-2 md:grid-cols-3 lg:grid-cols-4 gap-4 md:gap-5`
- Regional grid: `grid grid-cols-1 md:grid-cols-3 gap-4`
- Page container: `px-4 pt-6 pb-20 max-w-[1200px] mx-auto`

Exceptions:
- `mt-0.5` (2px) sub-label nudge inside `DestinationCard` — pre-existing v1.0 micro-spacing, kept as-is. New code should not introduce sub-4px spacing.
- `pb-20` (80px) bottom padding — clears the fixed mobile bottom-nav; pre-existing layout constant.
- `py-0.5` / `px-2` on the discount badge — pre-existing v1.0 badge sizing, kept unchanged.
- Touch targets: region pills and Retry/Clear-search buttons MUST be ≥40px tall (`min-h-[40px]` or `py-2` on `text-sm`). Existing pills already use `min-h-[40px]`.

## Typography

Font: `Outfit`. Phase 11 uses 4 sizes and 2 weights — no new type tokens.

| Role | Size | Weight | Line Height | Usage in this phase |
|------|------|--------|-------------|---------------------|
| Display | 30px → 36px (`text-3xl md:text-4xl`) | bold (700) | 1.2 (`tracking-tighter`) | Browse page `<h1>` — unchanged from v1.0 |
| Heading | 18px (`text-lg`) — 20px (`text-xl`) on the typographic fallback card | bold (700) | 1.2 | Typographic fallback card destination name; regional card title |
| Body | 14px (`text-sm`) | regular (400) / semibold (600) | 1.5 | Error-banner message; search-miss message; Retry/Clear-search button labels (`font-medium` 500 — see note) |
| Label | 12px (`text-xs`) | semibold (600) / bold (700) | 1.4 | Card price sub-label, discount badge, region-pill count |

**Weight contract:** the two primary weights are **regular (400)** and **bold (700)**. `font-medium` (500) and `font-semibold` (600) appear in pre-existing v1.0 code (button labels, card name) — they are kept where already used to avoid churn, but **no new component in this phase introduces additional weights**. New error-banner / skeleton / typographic-card / search-miss code uses only 400 and 700, except button labels which match the existing `font-medium` button convention.

**Typographic fallback card name:** `text-lg md:text-xl font-bold tracking-tight`, `text-white`, `text-center`. Long destination names wrap; clamp to 2 lines (`line-clamp-2`) so the name never overflows the `aspect-[4/3]` tile.

## Color

The 60/30/10 split for the browse surface:

| Role | Token | Light | Dark | Usage |
|------|-------|-------|------|-------|
| Dominant (60%) | `--color-background` / `--color-surface` | `#FFFFFF` / `#F4F4F5` | `#0A0A0B` / `#18181B` | Page background, region-pill inactive surface |
| Secondary (30%) | card surface | `#FFFFFF` + `--color-border` | `--color-surface-dark` `#18181B` + `--color-border-dark` | Destination cards, regional cards, skeleton placeholder cards |
| Accent (10%) | `--color-accent` | `#2979FF` | `#2979FF` | See reserved list below |
| Destructive | `--color-destructive` | `#E53935` | `--color-destructive-dark` `#EF5350` | See reserved list below |

**Accent (`#2979FF`) reserved for — exhaustive list this phase:**
- Active region pill background (`bg-accent text-white`)
- Retry button background (in the error banner)
- Clear-search button background (in the search-miss empty state)
- One stop of the typographic fallback-card gradient (`from-accent`)

Accent is NOT used for: card borders, card hover states, body text, links inside cards, or the skeleton shimmer. Card hover uses `--shadow-card-hover` (a blue-tinted shadow, already defined) — that is the only hover affordance and it is not counted as an accent fill.

**Destructive (`#E53935` / dark `#EF5350`) reserved for — exhaustive list this phase:**
- Inline error-banner border (`border-destructive/30`) and tint background (`bg-destructive/5`, dark `bg-destructive/10`)
- Error-banner message text (`text-destructive` / dark `text-destructive-dark`)
- The pre-existing discount badge (`#E53935` literal in v1.0 cards) — unchanged

Destructive is NOT used for the Retry button — Retry is a constructive recovery action and uses the accent fill. The error banner is destructive-tinted; the action inside it is accent.

**Typographic fallback-card gradient:** `bg-gradient-to-br from-accent to-primary` — `#2979FF` (top-left) → `#18181B` (bottom-right), 135°. White text at `text-white`. Same gradient in light and dark mode (it is a self-contained branded surface; it does not invert). The existing bottom scrim `bg-gradient-to-t from-black/70 via-black/20 to-transparent` still overlays the name/price chip on top of either the photo OR the typographic gradient — so the bottom name/price chip stays legible in both states.

**Skeleton placeholder color:** `bg-gray-200` light / `bg-gray-700` dark (`#E4E4E7` / token `#3F3F46`-range) — exactly matching `checkout-skeleton.tsx`. Neutral grey only; never accent-tinted.

## Component & State Inventory

The browse grid has a four-state contract. Every state below is mandatory and mutually exclusive at the grid level (header/nav/search bar/`WelcomeDiscountBanner` chrome stays mounted across all four).

| State | Trigger | What renders | Component |
|-------|---------|--------------|-----------|
| **Loading** | RSC awaiting `getCatalog()` / ISR miss | Shimmer skeleton grid — 12 placeholder cards in the real grid layout + a `h-10 w-48` title placeholder | `app/[locale]/browse/loading.tsx` → `DestinationGridSkeleton` |
| **Error** | `getCatalog()` returns `error: true` | Inline error banner above the grid + (if any) whatever destinations did return; chrome intact | `BrowseErrorBanner` inside `<BrowseClient>` |
| **Search-miss** | `searchQuery` non-empty AND filtered length = 0 | Plain "No destinations match …" text + prominent Clear-search button, centered, `py-16` | inline in `<BrowseClient>` |
| **Populated** | catalog rows present | Region pills + country grid + regional hero cards + comparison bar/sheet | existing render tree |

Sub-component state contracts:

| Component | State | Contract |
|-----------|-------|----------|
| `DestinationCard` | `image_url` present | Typographic gradient card renders first; `motion.img` photo cross-fades in **over** it (`opacity 0→1`, `blur(12px)→blur(0)`, 400ms `easeOut`). The typographic card stays mounted underneath — no flicker if the photo 404s. |
| `DestinationCard` | `image_url` null | Typographic gradient card only — bold destination name on `from-accent to-primary` gradient. No `<img>`, no flag, no placeholder graphic, no broken-image icon. |
| `RegionalPlanCard` | `image_url` present | Existing regional-plan-card photo treatment, unchanged. No new "Multi-country" frame or badge. |
| `RegionalPlanCard` | `image_url` null | Same typographic fallback card as country destinations (shared primitive). |
| `DestinationCard` | zero plans (`startingPriceCents === 0`) | Card still renders; price sub-label shows plain-text "No plans available" (i18n `browse.noPlans`) instead of `from {price}`. No mascot. |
| `DestinationCardSkeleton` | always | Dimensions identical to real card: `rounded-card`, `aspect-[4/3]`, same border. Pulse animation. |

**Skeleton animation:** use Tailwind's built-in `animate-[pulse_1.5s_ease-in-out_infinite]` (the exact class from `checkout-skeleton.tsx`) — opacity pulse, zero new CSS. A left-to-right shimmer sweep is **not required**; `pulse` satisfies the "shimmer skeleton" intent and keeps the cutover zero-config. (If a true sweep is later wanted, that is a separate polish item — out of scope here.) Skeleton card count: **12** (matches a full 3-row × 4-col `lg` grid; no layout shift when real data lands).

**Photo cross-fade (UXD-07) — exact spec:**
- Element: `motion.img` from `motion/react` (NOT `next/image` — `motion` cannot wrap it; CONTEXT locks `motion.img`).
- `initial={{ opacity: 0, filter: 'blur(12px)' }}`
- `animate={{ opacity: 1, filter: 'blur(0px)' }}`
- `transition={{ duration: 0.4, ease: 'easeOut' }}`
- The img is absolutely positioned over the typographic card (`absolute inset-0 object-cover`).
- The card's existing `group-hover:scale-105` zoom (500ms) is preserved on the photo.

**Card-entry animation (existing, preserved):** each card enters with `initial={{ opacity: 0, y: 12 }}`, `animate={{ opacity: 1, y: 0 }}`, staggered `delay: min(index,5)*0.03`, 250ms `easeOut`. Skeleton cards do NOT use entry animation (they appear instantly so the swap to real cards is the only motion).

## Copywriting Contract

All strings go through `next-intl`. New keys MUST be added to all 6 locale files (`messages/{en,pt,es,fr,ja,zh}.json`) under the existing `browse` namespace. EN copy is authoritative below; other locales translated.

| Element | i18n key | EN copy | Status |
|---------|----------|---------|--------|
| Primary CTA — error recovery | `browse.error.retry` | `Try again` | NEW key |
| Error state message | `browse.error.message` | `We couldn't load destinations right now. Check your connection and try again.` | NEW key |
| Primary CTA — search recovery | `browse.clearSearch` | `Clear search` | NEW key |
| Search-miss message | `browse.noResults` | `No destinations match "{query}"` | EXISTS — reword from `No plans for "{query}" yet` to `No destinations match "{query}"` |
| Zero-plans in-card label | `browse.noPlans` | `No plans available` | NEW key |
| Empty catalog (no rows at all) | `browse.empty` | `No destinations available yet. Check back soon!` | EXISTS — reused unchanged |

**Removed copy (no longer rendered):**
- `browse.noResultsSuggestion` (`Try a regional plan or browse popular destinations`) — the suggested-destinations row is dropped in favor of the Clear-search button. Leave the key in locale files for now (deletion is housekeeping, not Phase 11 scope) but it must not be rendered.

**Destructive actions:** None. Phase 11 is read-only — no delete, no irreversible action, no confirmation dialog. The error banner is a *recovery* surface, not a destructive one; Retry is safe to press repeatedly (idempotent re-fetch).

**Copy tone:** apologetic-but-brief for the error state; never blame the user, never use a mascot voice. No exclamation marks in error copy. The existing `browse.empty` keeps its friendly exclamation (pre-existing, not error copy).

## Accessibility Contract

| Surface | Requirement |
|---------|-------------|
| Skeleton grid | Skeleton container `aria-hidden="true"` (decorative); the page is in a loading route — screen readers get the route transition. No fake content announced. |
| Error banner | `role="alert"` on the banner so it is announced when it appears after a failed retry. Retry button is a real `<button>`, keyboard-focusable, label `Try again`. |
| Search-miss block | The message is a real `<p>`; Clear-search is a real `<button>`. After Clear-search resets the filter, focus returns to the search input. |
| Typographic fallback card | The destination name in the gradient is visible text (not `aria-hidden`); the card root keeps `role="button"` + `tabIndex={0}` (existing `Card` behavior). When the photo cross-fades in, the `motion.img` carries `alt={name}`. |
| Photo cross-fade | `motion.img` respects `prefers-reduced-motion` — when reduced motion is set, the photo appears at `opacity: 1` with no blur transition (gate the `motion` props or use `useReducedMotion()`). |
| Region pills | Existing `role="tablist"` / `role="tab"` / `aria-selected` preserved — unchanged. |
| Color contrast | Error text `--color-destructive` `#E53935` on `bg-destructive/5` (near-white) ≥ 4.5:1. Retry/Clear-search white-on-`#2979FF` ≥ 4.5:1. Typographic-card white-on-gradient: the `to-primary #18181B` end is fine; the `from-accent #2979FF` end gives white-on-`#2979FF` ≈ 3.0:1 — acceptable for `text-lg`+ bold (large text threshold 3:1), AND the bottom-scrim `from-black/70` overlay sits behind the name/price chip. Confirmed compliant for large bold text. |

## Implementation Notes for Planner & Executor

- **No new design tokens.** Everything resolves to existing `@theme` tokens in `src/styles/globals.css`. Do not add CSS variables.
- **No new dependencies.** `motion`, `next-intl`, Tailwind v4, `zustand` are all installed.
- **Skeleton dimensions are load-bearing** — if `DestinationCardSkeleton` does not match `DestinationCard`'s `rounded-card` + `aspect-[4/3]` + border exactly, the data-swap causes CLS and fails UXD-05's "no FOUC" intent.
- **Typographic fallback is a shared primitive** — build it once; both `DestinationCard` and `RegionalPlanCard` consume it for their null-`image_url` path. Do not duplicate the gradient JSX.
- **The error banner renders above the grid, not over it** — page `<h1>`, search input, `WelcomeDiscountBanner`, region pills, comparison bar all stay mounted in the error state.
- **Retry re-runs `getCatalog()`** via a server action (`refetchCatalogAction`), never `router.refresh()` — CONTEXT-locked.
- **No Bambu poses.** Remove the `BambuVideo` import from `destination-grid.tsx`/`browse-client.tsx`. `bambu-video.tsx` itself is untouched (not used on the browse grid anyway).
- **Dark mode is mandatory** for every new surface — skeleton, error banner, search-miss block, typographic card all have `dark:` variants verified against the dark tokens.
